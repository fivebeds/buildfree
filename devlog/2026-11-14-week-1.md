# Devlog 1: Why I'm building this

*November 14, 2026*

I run Contractors Helping Contractors Organization, a 501(c)(3) in National City that supports small contractors and tradespeople across San Diego. Over and over, the contractors I talk to are running real jobs out of text messages, notebooks, and spreadsheets. The tools that would help, like Procore and Buildertrend, are built and priced for much bigger companies.

So I'm going to build a free one. It will be hosted by CHCO, so contractors just sign up and use it, with nothing to install or pay for. The first version covers the basics: a contractor creates an account, adds clients and projects, and keeps daily logs with job photos. After that come estimates, change orders that homeowners can approve, a simple schedule, and a client portal.

I'm also learning to code as I go. I'm in the StartupHakk apprenticeship studying C#, JavaScript, jQuery, and REST APIs, and I decided to build this in exactly those tools so every hour spent on the project is also practice. Procore runs on Ruby on Rails and React, and Buildertrend runs on C# and .NET with React, so the C# route lines up with the same kind of software I'd work on in a real job. I'm using Claude to help plan the project and draft code, and I'll be posting what works and what breaks.

This week I set up the repo and wrote the first draft of the backend: an ASP.NET Core API with sign up, log in, clients, and projects, and a database setup that runs locally with Docker. Every company's data is kept separate by account, which matters a lot when you're hosting other people's businesses. I haven't tested it end to end yet, so that's the first job next week.

If you're a San Diego contractor and want to try it or tell me what would actually help on your jobs, I'd love to hear from you at kyle@chcorg.net.
